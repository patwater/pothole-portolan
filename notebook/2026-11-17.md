# 2026-11-17, second run: Extract san-francisco

Behavior: `extract` (interactive session). Phase 1, no `PAUSE`, last three notebook entries and agenda read.

## What was done

1. Converted the nine archives to text in the scratchpad and read them in full for the relevant sections. Confirmed the Public Works table column order against a rendered image of slide 7.
2. Wrote `scripts/extract_san_francisco.py`. It ties each value to anchor text in an archive, cross-checks the awards table, and refuses to write if anything fails. It preserves any `confidence` Assess has set.
3. Wrote 18 claims to `cities/san-francisco/claims.yaml`, all `provisional`: 10 `measured_condition`, 5 `spending`, 3 `policy`. The ledger validates and the content checks pass apart from the missing dossier.
4. Corrected the source inventory (below) and added the 2026 release as a new `listed` source.
5. Recorded corrections, the band schemes, unresolved conflicts and what was not extracted in `cities/san-francisco/notes.md`. Added a claim-kind request to the open proposal.

## Mistakes caught during the run

- **Discover misattributed a source.** The page I archived as the "January 2026 release" is the January 2024 release. I had taken a search snippet's date for the page I was listing. I renamed the source id, corrected its notes, and listed the real 2026 page separately.
- **A wrong value nearly shipped.** The first extraction read "4 blocks resurfaced" because it matched a slide footer page number. I caught it only because the script prints every value. The script now anchors on the full slide sequence. There is no automated test for this trap yet.
- **A stale search snippet became a "discrepancy".** The "good = 64 to 84" band is not on MTC's page, so Discover's second discrepancy was partly an artifact. I have replaced it with the four band schemes that the archives actually contain.
- **The awards table does not add up exactly** ($132.9M of rounded rows against a stated $133.0M). I allowed for rounding and said so in the claim's caveats rather than forcing a match.

## What was learned

- Four incompatible condition band schemes and three different survey-interval statements exist in San Francisco's own documents. A dossier has to quote each source's own bands and never merge them.
- The scorecard pages keep their headline numbers in dashboards, so the archived HTML holds methods but not values. Values need the datasets behind them.
- The schema lacks a kind for program output, so three claims are recorded as `spending` with a caveat. Requested in the proposal.

## What was learned

- "Supported" is narrower than it sounds. It certifies faithful reporting of a source, not the truth of a city's own figure, and two supported claims contradict each other (two-year versus three-year survey cycles). The dossier must present both.
- The assessor itself had a flaw: a missing archive crashed the run instead of demoting the claim. I found it only by testing against deliberately damaged data, which is why that test is now committed.
- Statements I had made from memory of the documents needed checking: the two-year inspection sentence appears 5 times in the Prop L document, not twice as I had implied. The script now counts instead of asserting.
